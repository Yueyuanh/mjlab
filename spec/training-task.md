# 训练任务规范

## 任务身份

- 每个任务必须有唯一、稳定的 Task ID，并注册 train env、play env、RL config 和 runner。
- Task ID 应遵循 `Mjlab-{Category}-{Terrain}-{Robot}-{Variant}` 的现有语义，避免把日期写进 ID。
- 新增、替代、阻塞或废弃任务时，必须更新 `docs/task_lineage.md`，保留历史 Task ID 和状态。
- 每个任务必须使用独立且可识别的 W&B project/tags，不能落入默认 `mjlab` 混合项目。

## 配置设计

- 动作空间必须列出受控关节、顺序、scale、offset、clip 和 actuator limit 的关系。
- 观测必须区分 actor/critic，说明单位、坐标系、归一化、历史、噪声和延迟。
- 奖励与终止项必须说明物理含义、符号、量纲/归一化和主要失效模式。
- train/play 差异必须显式：随机化、课程、命令采样、终止、episode 时长和可视化不能隐式漂移。
- 任务特有坐标约定必须写清楚，例如 body frame、heading frame、world frame 或接触顺序。
- 新变体应从明确基线继承，只覆盖必要差异。一次实验应当优先验证一个主要假设；若必须联动
  多项，报告中要承认无法单独归因。

## 分级验证

1. **静态测试**：配置可实例化，名称/维度/限位/顺序有效，关键不变量有单测。
2. **`1-sanity/`**：`zero` 和 `random` agent，无 NaN，reset、奖励、终止和接触行为正常。
3. **`2-smoke/`**：少量环境和迭代，验证保存、resume、日志、评估和视频管线。
4. **`3-pilot/`**：中等资源验证学习方向，提前定义停止条件和候选门槛。
5. **`4-full/`**：只放大已经通过 pilot 的配置，不在运行中修改源码或配置；结束后自动执行固定
   前进/后退 80% 速度评估。

smoke 成功只证明管线可运行，不证明策略能学会。训练回报升高也不等于任务目标达成。

## 热启动与续训

- 必须记录父 checkpoint 路径与 SHA-256、加载 actor/critic/optimizer 的范围、起始迭代和新增长度。
- 改变观测、动作语义、关节顺序或 normalizer 契约时，默认禁止直接续训；确需迁移时提供显式迁移
  代码和兼容测试。
- `max_iterations` 的含义必须按当前 runner 核对并写入 metadata，避免把“新增轮数”误当总轮数。
- 探索噪声是否继承或重置必须记录。

## 完成定义

一个训练任务只有同时满足以下条件才可称为“完成”：训练进程正常结束、最终 checkpoint 有哈希、
有效配置和代码状态可追溯、固定协议评估已完成、候选选择有记录。否则只能写“训练结束”、
“中断”或“待评估”，不能写“最终模型”。
