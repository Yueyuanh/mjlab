§1

资产：去闭链、镜像惯量

19 links / 18 joints / nq 25 / nv 24

上一代的膝是四杆闭链，仿真里要三个关节加等式约束才能表达一个膝。 v035 改成单轴直驱：一个膝只有一个自由度，传动比恒 1:1，没有零位偏置，equality 约束数归零。 代价是电机要直接承受全部力矩，所以膝关节从 4310 换成 4340。

URDF 的腿不是完全直立，而是按 CAD 初始姿态留了偏置：相对伸直腿 hip_pitch 20°、knee 20°、ankle 10°。 mjlab 的站高 0.2296 m 由这个姿态正解得到，不沿用旧版常数。

左右惯量镜像

导出时右腿/右臂的惯量是另算的。以左侧为基准镜像后覆盖右侧： 质心按 y → −y，非对角惯量项各有一个 ±1 符号规则 （例如 hip_roll 三个都是 +1，knee 是 −1 / +1 / +1）。

也就是说：质量两侧本来就相同，惯量对角项也一致，真正不一致的是质心偏移和个别非对角项。 数值不大，但直驱膝对腿部惯量比敏感，所以仍按左侧统一覆盖。 这里的一致性只说明「右 = 镜像(左)」，不说明「左本身是对的」——后者要靠 CAD 质量属性，本次没有独立复核。

E1 走不起来不是 bug：它带 standing_* 奖励族、25% 的零命令样本， 推扰只施加给已经在移动的机器人，而跟踪奖励的 std 是 0.5，远宽于 ±0.2 的命令—— 站着就能拿 0.92 的跟踪分。这组设置的结局必然是站桩，保留它是为了当对照。

walk 把「站着很赚」这条路堵死：删掉 standing 族、零命令样本降到 10%、推扰对全员施加、 跟踪权重提到 5 并换成 Huber，加上 directional_progress +3.0。 v2 只改三处：角速度跟踪 std 0.40→0.35、权重 2.0→2.5；线速度 std 0.20→0.30；body_ang_vel −0.05→−0.12。 v3 把这三处全部回退，只加一个偏航 Huber 项。

奖励权重预算

单项罚的单步量级不要超过进度奖励的三成。v034 曾把 straight_base_roll_rate 设到 −0.60（单步罚 4.8，而进度奖励只有 3.5）， 70 轮就把一个会走的策略打回站桩。这条教训在 v035 的所有任务里沿用。

C

转向只做到 62%。命令 0.15 rad/s 实测 0.093，MAE 0.112。

B、C 是同一类问题，但不是「std 太宽」这么简单。指数型跟踪奖励的回复力 正比于误差本身∂/∂e exp(−(e/s)²) = −2e/s² · exp(−(e/s)²)， 误差越小坡度越平。v035 walk 的角速度 std 已经是 0.40（基类默认 0.707）， 0.09 rad/s 的漂移对应 exp(−(0.09/0.40)²) = 0.95—— 几乎满分，而修掉它必须改步态，代价不小。于是策略选择忽略。

要治这个，三条路：收紧尺度、补一个在误差小的地方也保持恒定梯度的项、 或者把正确行为的收益抬上去。v2 走了第一条，v3 走了第二条，两次都退步； v5 走了第三条，成功了。三段的完整过程见下。

C

前进开始超速。实测 0.240 vs 命令 0.20，MAE 从 0.015 涨到 0.040。同时 wz 的 MAE 涨到 0.345——均值漂移是小了，但瞬时偏航振荡剧烈，这是「均值好看、行为更差」的典型。

三处同时改导致归因不干净，但现象指向同一个结论：在非纵向命令下，策略学会了「站着不动」这个更省事的解。 这也解释了为什么它同时把转向和站立档都推到了双足支撑。

所以 v2 不作为交付策略。 下一轮（v3）把这三处全部回退，改为只加一项非饱和的偏航 Huber 代价—— 指数型跟踪奖励的回复力正比于误差本身，误差越小坡度越平，正好是最需要纠正的那一段没力气。

v3 把 v2 的三处改动全部回退，只加一项：angular_velocity_huber， 权重 −0.30、delta = 0.25。理由是指数型跟踪奖励在误差小的地方坡度极平， 而 delta 之外的 Huber 保持恒定梯度，正好补上「最该纠正却推不动」的那一段。 从 v1 末轮热启动，跑 1500 轮。

1

gait_contacts_smooth_120（+1.8）是无条件项。它奖励「实际接触相 = 参考接触相」，而参考相在静止时正好是全部支撑——站着不动就能拿满这 1.8。侧移/转向一旦真动起来，接触相被打乱，反而掉分。

2

forward_* 系列（directional_smooth_gait_mismatch、forward_velocity_shortfall、 directional_sole_cost）都乘了 forward_weight(env)，非纵向命令时输出为 0， 不构成对抗。改法明确：把 gait_contacts_smooth 改成按实际运动门控， 并把进度项扩成三轴。这是结构性改动，不在本次微调范围内。

代价：前进速度从超速 7% 变成欠速 7%。0.214 → 0.187（命令 0.20），MAE 0.015 → 0.015。后退反而更准了（v1 超 22% → v5 超 7.6%）。

三档微调放在一起看，结论很干净：v2 和 v3 都在加重「跟踪不上」的代价，v5 是把「跟踪上」的收益抬到与线速度同量级。 同一个站桩解，在前两次的奖励下「罚得少、拿得多」，在 v5 下「罚得多、拿得少」——策略于是真的去转向了。

这一代的膝是速度受限，不是力矩受限。三档膝关节力矩都只有 2.0–5.5 N·m，相对 40 N·m 峰值几乎空载；真正的瓶颈是转速。选 4340 是为了承受闭链改直驱后的力矩，但从实际工况看，膝关节更需要的是转速。

2

walk 需要 2.3–3.2 倍额定转速的膝摆动。DM 电机的「额定 36 rpm」是连续工作点，空载通常 1.5–2 倍，但没有官方数据。而仿真里配的是 BuiltinPositionActuatorCfg——这个执行器类型下 velocity_limit 根本不生效，没有任何扭矩–转速降额，所以仿真允许膝以任意速度摆动、且始终能拿满 40 N·m。这是当前最大的 sim2real 差距。

另一个细节能佐证这条：膝关节的行程远没用满。walk 只在 −19°…+24° 之间工作， 而限位是 −30°…+90°——摆幅小、频率高，速度是靠步频堆出来的， 代价全落在膝的角速度上。要保住转速余量，应该往「步幅大一点、步频低一点」的方向调， 而不是继续收摆幅。

crawl 档能跑通，恰恰是因为它慢——膝速 92% 额定，还在能力边界内。 这条结论的直接后果是：行走档的步态在实物上大概率跑不出来，除非拿到 4340 的真实空载转速， 并确认 10 rad/s 量级的膝摆动在电机能力内。

§7

已知问题与下一步

按优先级排列

P0

膝速超额定 2.3–3.2 倍。需要 4340 的真实空载转速。拿到后跑 V035-Biped-Walk-V4（DC 电机模型）重训，或把行走命令压到 0.1 m/s 量级。

P1

crawl 侧移 / 转向。奖励结构与命令方向冲突：gait_contacts_smooth 无条件给站桩补贴，directional_progress 只看纵向。需把前者按运动门控、后者扩成三轴。

P2

walk 转向 62% → 71%（已定位并改善，未收干净）。根因不是 std 尺度，是角速度跟踪的相对权重只有线速度的十分之一（v2/v3 两轮都改错了方向）。权重 2.0→6.0 后转向 0.107、漂移 0.013。剩余缺口主要是转向档的瞬时振荡：均值偏差只有 0.043，而 MAE 是 0.087——下一步是加航向闭环，或对转向档单独加课。

P3

手臂「举起」已修（2026-10-29），代价是旧 checkpoint 前进掉 15%。根因是 v035 的 arm_roll 轴是 (-1,0,0)，而 v033/v034 是 (+1,0,0)：从 v034 抄来的默认位姿 L−53°/R+53° 在 v035 上把上臂抬到水平面上方 53°（渲染出来就是双手举起），ARM_BOUNDS_DEGREES 的 (45, 53) 窗口也在奖励同一姿态，所以六次训练都稳定停在 ±50°。现改为 L+53°/R−53°（手从肩上 8.4 cm 落到肩下 8.4 cm），并把左右 arm_roll 窗口镜像为 右 (−53,−45) / 左 (45,53)。动作是相对默认位姿的，已交付的六个模型 play 时手臂自动下垂：实测 E1 站立 arm_roll L+54.9°/R−55.8°、walk 前进 L+56.9°/R−56.7°。

同 seed / 16 env / 8 s 的 A/B（手臂上举 → 下垂）：E1 站立漂移 0.0009 → 0.0008 m/s；walk v1 前进 0.214 → 0.183（wz 漂移 +0.092 → −0.032）；walk v5 前进 0.187 → 0.159（wz 漂移 −0.013 → −0.153）。全部 falls=0，但前进掉约 15%。原因不是数值 bug——use_default_offset 让 arm_roll 目标整体平移 106°，手臂质量分布与绕 z 转动惯量跟着变，而这六个策略学的是上举姿态下的步态。要恢复原指标必须按新默认位姿重训；想退回上举姿态比较，改的是同一处配置。旧的绝对关节角记录与旧窗口下的 reward 也与新配置不可比。

P4

站立用满髋偏航。walk 站立档 hip_yaw 左 −10.3°、右 +13.7°，而限位只有 ±14.9°——用掉八成，是机构层面的余量提醒。

P5

4340 转子惯量是估算值。当前按「4310 的 4 倍」估，没有实测。转子惯量直接影响直驱膝的高频动态，实测后应重新校核 PD 增益。

P6

鲁棒性未做。本次全部是标称评估，无域随机化。生产前需要补 foot friction / base COM / encoder bias / 外力推扰的随机化评估。

还有两条方法论上的观察值得复用。 一是奖励设计比网络容量的影响大得多：同样的机器人、同样的观测、同样的 PPO， 只改奖励口径，E1 只会站着、walk 能走。 二是「加重错误的代价」和「抬高正确的收益」不是一回事：v2、v3 都在加重跟踪不上的代价， 两次都把转向压到 5% 以下；v5 只把正确行为的收益抬到与线速度同量级，一次就把四档全做上去了。 改奖励之前先问一句：在当前权重下，策略「什么都不做」能拿多少分？
