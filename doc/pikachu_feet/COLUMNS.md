## A. 步态相位与计时

数据源：接触传感器 `feet_ground_contact`。**左右标签正确。**

### `foot_contact/{left,right}` — 触地标志

**单位** 0/1 · **参考系** 无 · **源** 传感器

```
contact = (found > 0).float()
```

**含义**：该帧该脚（踝 body 子树，含 5 根脚掌胶囊）与地形是否几何接触。

**实测**：左右各 n=200，nan=0，min=0 / max=1 / mean=**0.56**（每脚 56% 的帧在接触）。
接触序列规整：单支撑交替，每段支撑 **14 帧**（0.28 s）、腾空 **10–11 帧**（0.20–0.22 s）；
换脚处双支撑 **1–2 帧交替**（因支撑 14 + 腾空 11 = 25 帧周期、半周期 12.5 帧 → 重叠约 1.5 帧），
启动阶段 3 帧，全序列共 26 个双支撑帧。

**判读**：二值 {0,1}。稳态行走应在 0/1 间规律交替，episode mean ≈ 时间占空比，正常 0.5–0.6。
异常：某脚 mean→0（从不落地）、mean→1（常驻接触、对侧不落地）、或长期恒定（卡住）。

**坑**：`found > 0` 是**几何匹配计数，不是力阈值**——零力但几何接触仍记 1。
`reduce="netforce"` 把整个踝子树合并为一个主元，所以单列 = 整只脚，不区分脚掌/脚跟/脚尖。

---

### `foot_phase/{left,right}` — 归一化步态相位

**单位** 0~1 · **参考系** 无 · **源** 传感器计时器

```
cycle = clamp(last_contact + last_air, min=1e-3)
have_cycle = (last_contact + last_air) > _MIN_CYCLE_S     # 0.05 s
phase = remainder(where(contact>0.5, contact_time/cycle,
                                      (last_contact + air_time)/cycle), 1.0)
```

**含义**：0 = 刚触地（支撑开始），趋近 1 = 该周期结束（下次触地前）。

**实测**：nan=2（前 2 帧）。左 mean 0.4963 / p50 0.5050；右 mean 0.4841 / p50 0.4608。

**判读**：0~1 循环，连续帧单调推进、跨 1 环绕。相邻帧步长 ≈ `step_dt / 周期` ≈ 0.04。
异常：大量 NaN（脚一直无完整周期）、相位长时间不推进、左右相位差长期偏离 0.5。

**坑**：分母 `cycle` 是**上一个完整周期**，不是当前周期。若当前支撑比上一周期长，
相位会在仍接触时就越过 1 环绕（本录 frame 28 在接触中从 0.962 跳到 0.038）；
更短则未到 1 就离地。所以它**不是严格的"当前周期进度"**。

---

### `foot_duty/{left,right}` — 支撑占空比

**单位** 0~1 · **参考系** 无 · **源** 传感器计时器

```
duty = clamp(last_contact / cycle, 0.0, 1.0)   # 同上 cycle
```

**含义**：**上一完整周期**的支撑时长 / 周期时长。**锁存量**，随每次支撑↔腾空跃迁更新。

**实测**：nan=2。左 mean 0.5355（集中 0.56–0.60）；右 mean 0.5364，但有一个
**0.8261 的离群周期**（上一周期腾空异常短），std 约为左的 1.6 倍。

**判读**：0.5 = 支撑腾空各半。稳态行走正常 0.4–0.7。异常：≈1（拖步）、≈0（几乎不落地）、
剧烈跳动（周期不规律）。

**坑**：是**上一完整周期**的锁存值，不是当前周期、也不是全 episode 平均。
`reduce="mean"` 会把每个中间锁存值再平均，与 `foot_contact` 的时间占空比含义不同（通常接近）。

---

### `foot_stance_time_s/{left,right}` — 当前支撑已持续时长

**单位** s · **参考系** 无 · **源** 传感器计时器

```
contact_time = sensor.data.current_contact_time[:, perm]
```

**含义**：当前这一支撑相**已持续**了多久。接触中每物理步 +dt 单调增，离地立即归 0。

**实测**：左 mean 0.0778 / p50 0.035 / p95 0.26 / max **0.28**；右 mean 0.0791 / max 0.28。
所有取值均为 **0.005 s 的整数倍**（物理步长）。

**判读**：看**接触帧内的峰值**，不要看整段 mean。支撑段从 0.005 递增到 ≈0.28 s。
异常：接触中不增长（计时器坏）、峰值远超步态周期（脚黏地）。

**坑**：**不是**平均支撑时长，也不是"上一次支撑时长"——它是**进行中计时器，腾空时为 0**。
`reduce="mean"` 被大量 0 拉低（本录 0.078，而真实单次支撑 ≈0.28），**不能**当 duty × period 用。
要平均支撑时长须用 `last_contact_time`（本模块未单独录列）。

---

### `foot_air_time_s/{left,right}` — 当前腾空已持续时长

**单位** s · **参考系** 无 · **源** 传感器计时器

```
air_time = sensor.data.current_air_time[:, perm]
```

**含义**：当前这一腾空相**已持续**了多久。腾空中每物理步 +dt 单调增，一触地立即归 0。

**实测**：左 mean 0.0479 / p50 **0** / p95 0.195 / max **0.215**；右 mean 0.0474 / max 0.215。
p50 = 0 是因为 56% 的帧在支撑。

**判读**：看腾空帧内的峰值。异常：腾空时该值不增长、峰值过大（跳步/长时间离地）。

**坑**：同 `foot_stance_time_s`——进行中计时器，支撑时为 0，**不是**平均/上次腾空时长。

## B. 接触力与冲击

数据源：接触传感器 `reduce="netforce"` 的世界系净力。**左右标签正确。**

### `foot_force_normal_n/{left,right}` — 法向支持力

**单位** N · **参考系** 世界系 · **源** 传感器

```
force_n = clamp(-force_w[..., 2], min=0.0)   # force_w = sensor.data.force[:, perm, :]
```

**含义**：世界系净接触力竖直分量的**取反** = 地面给脚的法向支持力。**真值**，可直接当承重读数。

**实测**：左 mean 33.50 / p50 51.70 / p95 79.66 / max 91.87；右 mean 34.67 / p50 46.15 /
p95 85.26 / max **102.53**。**左右之和 ≈ 68.17 N ≈ mg**（6.76 kg × 9.81 = 66.4 N）。
右脚峰值与 p95 更高，左脚中位略高。

**判读**：双脚之和应 ≈ mg（~66 N）。显著偏小 = 漏接触/悬空；单脚长期 ≈ 体重 = 另一脚未承重。

**坑**：MuJoCo 接触力方向是 primary→secondary（脚→地面），故取负号；`clamp(min=0)`
把数值上的负值吞掉。netforce 每只脚只有**一个净力向量**，没有空间分布
（脚掌两端受力差异要看 `foot_pressure_pa`）。

---

### `foot_force_tangent_n/{left,right}` — 切向（剪切）力

**单位** N · **参考系** 世界系 · **源** 传感器

```
force_t = norm(force_w[..., :2], dim=-1)
```

**含义**：世界系净接触力**水平分量（xy）的模长** = 脚底切向/剪切力。

**实测**：左 p50 10.07 / p95 16.49 / max 19.78 / mean 7.34；右 p50 7.02 / p95 **27.93** /
max **31.86** / mean 7.72。右脚尾部明显更重（std 8.83 vs 7.03）。

**判读**：常态 p50 7–10 N。切向力不应超过 μ·法向；`foot_friction_util` ≤ 1 为安全，
本录左脚 max util = 1.0000 **已触打滑极限**。

**坑**：是水平**模长**恒 ≥0，丢失了切向方向。单看它不知道离摩擦锥还有多远，
必须配合 `foot_ground_friction_mu` 与 `foot_friction_util`。

---

### `foot_force_rate_n_s/{left,right}` — 法向力变化率

**单位** N/s · **参考系** 世界系 · **源** 传感器（差分） · **瞬时量**

```
force_rate = (force_n - prev_force_n) / step_dt    # step_dt = 0.02 s
```

**含义**：法向力逐控制步的一阶差分 = 瞬时加载/卸载速率。触地帧大正峰，离地帧大负峰。

**实测**：左 min **−2902.79** / p50 0 / p95 1869.13 / max **4593.64** / mean 15.59；
右 min −1726.81 / p50 0 / p95 2472.03 / max **4847.30** / mean ≈0。
左脚卸载负峰更深，右脚加载正峰更高；mean≈0 因正负抵消。

**判读**：稳态支撑与腾空 p50 = 0；触地/离地尖峰量级 ±2000~4900 N/s。
稳态支撑若仍有大幅振荡 = 接触抖动/求解器不稳；峰值越大落地越硬。

**坑**：是 50 Hz 录制的**逐控制步差分，不是连续导数**；真实触地在一个物理子步内完成，
此值会**低估**真实冲击率。有正负号。`reduce="max"` 会被最大正速率主导，卸载负峰在
tfevents 里看不到。锁存版见 `foot_impact_rise_n_s`。

---

### `foot_impact_peak_n/{left,right}` — 本次支撑的法向力峰值

**单位** N · **参考系** 无 · **源** 传感器 · **区间锁存量**

```
rising = (contact > 0.5) & (prev_contact <= 0.5)
impact_peak = where(rising, 0, impact_peak)
impact_peak = maximum(impact_peak, force_n * contact)
```

**含义**：**本次支撑内**（自最近一次触地起）出现过的最大法向力。
锁存量——不是瞬时量，也不是全 episode 累计。腾空时 `force_n * contact = 0`，峰值保持不降。

**实测**：左 p50 83.40 / max 91.87 / mean 83.18 / std 9.41；右 p50 97.42 / max 102.53 /
mean 95.56 / std 12.91。右脚锁存峰值系统性更高，左脚更稳。
两脚的 max 各自等于对应 `foot_force_normal_n` 的 max。

**判读**：正常 ≈ 该次支撑的最大承载（p50 83–97 N，略高于体重）。长时间保持 0 = 该脚尚未触地；
持续远高于体重 = 落地过猛。`reduce="max"` 才是全 episode 最大。

**坑**：锁存量，同一支撑内保持不变，腾空期间既不更新也不重置。首帧/重置后从 0 起，
`min = 0` 表示该支撑内还没读到接触。**不要当瞬时法向力读**。

---

### `foot_impact_rise_n_s/{left,right}` — 本次支撑的最大加载速率

**单位** N/s · **参考系** 无 · **源** 传感器 · **区间锁存量**

```
impact_rise = where(rising, 0, impact_rise)
impact_rise = maximum(impact_rise, clamp(force_rate, min=0.0) * contact)
```

**含义**：**本次支撑内**法向力的最大上升速率（只取正速率），表征落地冲击的陡峭度。
与 `foot_impact_peak_n` 共享同一支撑窗口。

**实测**：左 p50 4150.41 / max 4593.64 / mean 3903.28 / std 726.86；
右 p50 3096.62 / max **4847.30** / mean 3243.20 / std 847.81。
左脚中位更高更集中，右脚尾部更高。

**判读**：越大落地越硬。参考 p50 3.1–4.2 kN/s、max 4.6–4.8 kN/s；**无绝对阈值**，
看趋势与左右对称。

**坑**：锁存量，`rising` 沿清零；**只累计正速率**，卸载负速率不计。
基于 `step_dt = 0.02 s` 的差分，50 Hz 下会低估真实冲击陡度。

## C. 接触几何与压力

数据源：同名踝 body 下的 25 个虚拟 taxel／脚到地面平面的距离。

> 全组依赖 `SOLE_COMPLIANCE_M = 0.002`（2 mm 柔性鞋垫）与"地面是水平面"两条假设，
> 见 [README 3.2 / 3.3](README.md#32-地面被当作高度-ground_z-的水平面)。
> taxel 布局：每脚 25 个（5 根胶囊 × 5 点），`k = y_row * 5 + x_col`（先 y 行再 x 列），
> 列名 `{side}_foot{k}`，k = 0..24。**k 是网格序，不是传感器物理编号。**
> `cell_area_m2 ≈ 3.328e-4 m²`（鞋底投影面积 8.32e-3 m² / 25）。

### `foot_penetration_m/{left,right}` — 最深 taxel 的穿透深度

**单位** m · **参考系** 世界系（z 向） · **源** taxel · **瞬时量**

```
penetration = -(taxel_w[..., 2] - grid.ground_z)
pen_f = _by_side(penetration)
out = pen_f.clamp(min=0.0).max(dim=-1).values
```

**含义**：该脚 25 个 taxel 中**最深的一个**此刻陷到地面平面以下的深度。

**实测**：左 p50 0.591 mm / p95 3.998 / max **5.084** / mean 1.106；
右 p50 0.459 / p95 3.578 / max 4.555 / mean 0.947。（此左右已按"名 left/名 right"读。）

**判读**：`< 1 mm` 属正常压痕；接近或超过 **2 mm**（鞋垫厚）说明刚体脚几何上已切进地面平面，
几何代理与真实接触开始分家。

**坑**：`clamp(min=0)` 把腾空写成 **0 而非 NaN**——0 只表示"无 taxel 低于平面"，
**不等于没接触**。只报 25 个 taxel 的最大值，不含接触分布。

---

### `foot_contact_area_m2/{left,right}` — 接触面积

**单位** m² · **参考系** 无 · **源** taxel · **瞬时量**

```
in_contact = compression > 0.0        # compression = clamp(2mm - gap, min=0)
sensor_count = in_contact.sum(-1)
contact_area = sensor_count * grid.cell_area_m2
```

**含义**：接触 taxel 数 × 每 taxel 名义面积。**几何代理**接触面积。

**实测**：左 max **8.32e-3**（= 满垫 25 taxel）/ mean 3.241e-3；
右 max 4.326e-3（= 13 taxel）/ mean 1.135e-3。

**判读**：满垫 = 8.32e-3 m² = **83.2 cm²**。取值只能取 26 档（k × 3.328e-4，k = 0..25）。

**坑**：`cell_area` 是"鞋底投影面积 / 25"的**名义值**，不是实测。"面积"是 2 mm 压痕范围内的
**taxel 计数换算**，不是真实接触斑面积。

---

### `foot_contact_fraction/{left,right}` — 接触 taxel 占比

**单位** 0~1 · **参考系** 无 · **源** taxel · **瞬时量**

```
contact_fraction = sensor_count / n_per_foot     # n_per_foot = 25
```

**实测**：左 mean 0.390 / p95 1.0 / max 1.0；右 mean 0.136 / max 0.52。
量化步长 1/25 = **0.04**。

**判读**：0 = 腾空；1 = 整只鞋底落在 2 mm 接触范围内。

**坑**：与 `foot_sensor_count` 是同一数据的两副面孔（只差除以 25），
**不要当两个独立指标各画一图**。左右差异大是"接触 taxel 数"的差异，
**不是力分配**——别直接读成两只脚负载不均（负载看 `foot_force_normal_n`）。

---

### `foot_sensor_count/{left,right}` — 接触 taxel 计数

**单位** 个（0~25 整数）· **参考系** 无 · **源** taxel · **瞬时量**

```
sensor_count = in_contact.sum(-1)
```

**实测**：左 p50 3 / p95 25 / max **25** / mean 9.74；右 p50 3 / p95 10 / max 13 / mean 3.41。

**判读**：0 = 腾空，25 = 整只鞋底接触。整数计数，按档位看（每档 = 1 个 taxel = 3.328e-4 m²）。

**坑**：这个"25"是 **taxel 阵列规模**（5 胶囊 × 5 点），**不是硬件传感器数量**。

---

### `foot_pressure_pa/{left,right}_foot{k}` — taxel 压力分布

**单位** Pa · **参考系** 无（分子取世界系法向力大小，几何权重在踝体系算） · **源** 传感器×taxel
· **瞬时量** · **每脚 25 列，共 50 列**

```
share = weight / weight_sum.clamp(min=1e-9)      # weight = _by_side(compression)
pressure = share * force_n.unsqueeze(-1) / grid.cell_area_m2
```

**含义**：把该脚**实测**法向力按各 taxel 的压痕加权分摊，再除以 taxel 面积。
**力的总量是传感器真值，空间分布是几何代理。**

**实测**：最热 taxel：`right_foot4` max **285 339** Pa / mean 13 249；`left_foot4` max 252 511。
次热：`right_foot0` max 140 500、`right_foot9` max 93 515、`left_foot9` max 80 951。
`right_foot17/18/19/21/22/23/24` **全为 0**（整段 200 帧从不接触）。

**判读**：理论上限 = `force_n / cell_area` ≈ 100 N / 3.328e-4 ≈ **300 kPa**（单 taxel 独担全脚载荷）；
均匀分摊时约几十 kPa。

**坑（三条，都要紧）**：

1. 新录制中左右列按同名脚的传感器力与 taxel 几何配对；修复前旧 CSV 的 pressure 列仍是交叉配对。
   每 taxel 压力仍是**空间代理**，不是硬件压力真值。
2. 接触 taxel 很少时单点可到 ~300 kPa，物理上不可能。
3. `k` 是 `(y, x)` 网格序，不是传感器物理编号。0 列不代表传感器坏，是那个位置从不接触。

## D. 足底姿态

数据源：同名踝 body 的 25 个 taxel 法向均值（纯刚体几何，不含力信息）。

> 三者非独立：`sin²(tilt) = sin²(pitch) + sin²(roll)`。
> 符号绑世界轴；`pitch/roll` 是相对**世界**系的角度，**不是踝关节角**。

### `foot_tilt_deg/{left,right}` — 鞋底与地面夹角

**单位** deg · **参考系** 世界系 · **源** taxel · **瞬时量**

```
sole_up = normalize(-normal_f.mean(dim=-2))          # 鞋底朝上的法向
tilt = rad2deg(acos(clamp(sole_up[..., 2], -1, 1)))  # 与 +z 的夹角
```

**含义**：水平踩实 = 0°。每帧都算（含腾空相），与是否接触无关。

**实测**：左 min 0.063 / p50 4.34 / p95 23.03 / max **28.62** / mean 6.76；
右 min 2.90 / p50 12.57 / p95 17.80 / max 19.15 / mean **12.18**。

**判读**：稳态支撑应接近 0–10°；> 20–25° 表示鞋底明显没踩平（或该帧在摆动）。
**左脚触地/支撑时能到 28.6°**（frame 16，该帧 `foot_contact = 1`），**摆动相最大约 20°**（frame 14）。

**坑**：是 taxel 阵列的**几何法向均值**（非接触力加权），纯踝 body 姿态的刚体函数，
不含力信息、不随 `SOLE_COMPLIANCE_M` 变。

---

### `foot_pitch_deg/{left,right}` — 俯仰分量

**单位** deg · **参考系** 世界系 · **源** taxel · **瞬时量**


## E. CoP 与摩擦

**CoP 三列来自同名脚 taxel（踝 body 系）；摩擦三列来自接触传感器。**

### `foot_cop_x_m/{left,right}` — 压心纵向位置

**单位** m · **参考系** **踝 body 系** · **源** taxel · **瞬时量，无接触为 NaN**

```
weight = _by_side(compression)                       # 压痕即权重
cop_local = (local_f * weight.unsqueeze(-1)).sum(-2) / weight_sum.clamp(min=1e-9)
cop_x = cop_local[:, i, 0]
```

**含义**：接触压强加权质心（CoP）在踝体系的 x 分量（脚掌纵向）——这只脚把体重压在纵轴的哪一端。

**实测**：左 n=115 / nan=85，min −0.0385 / p50 0.00751 / p95 0.0400 / max 0.0400 / mean 0.01336；
右 n=117 / nan=83，min −0.0400 / p50 0.00347 / max 0.0400 / mean 0.00882。
左右都常贴 ±0.04 上界。

**判读**：取值恒落在 taxel 网格 x 范围内（≈ ±0.04 m）。靠近中点 = 载荷居中，贴到 ±0.04 = 全压一端。

**坑**：无接触帧是 **NaN**（左 85/200、右 83/200），**不是 0**。CoP 是接触 taxel 局部坐标的
**凸组合**，永远落在接触区内不会越界。建立在"地面是水平面"假设上。

### `foot_cop_y_m/{left,right}` — 压心横向位置

**单位** m · **参考系** **踝 body 系** · **源** taxel · **瞬时量，无接触为 NaN**

```
cop_y = cop_local[:, i, 1]     # 与 cop_x 同一次加权平均的 y 分量
```

**实测**：左 p50 −0.00276 / min −0.0280 / max 0.00724 / mean −0.00714；
右 p50 **−0.02750** / p95 −0.02265 / max −0.00281 / mean −0.02561。
右脚长期贴负端，左脚多在近 0（居中）。

**判读**：y 网格约 [−0.028, +0.007] m；越贴负端 = 载荷压在某一侧边。

**坑**：**左右脚踝系原点/朝向不同，跨脚比绝对值会误判**，只看各自的时间变化与是否贴边。
左右不对称不要当成 bug——右脚 CoP_y 贴负端与其 roll 一致。

### `foot_cop_margin_m/{left,right}` — 支撑边界裕度

**单位** m · **参考系** **踝 body 系** · **源** taxel · **瞬时量，无接触为 NaN**

```
rel = local_xy - cop_local[..., None, :2]
proj = where(contact_f.unsqueeze(-1) > 0.5, rel @ _hull_dirs.T, -1e6)   # 32 个方向
margin = proj.max(-2).values.min(-1).values        # min_u max_i (p_i - c)·u
```

**含义**：CoP 到当前**接触区凸包**边界的最小距离。0 = CoP 贴接触区边缘（濒临翻倒）。

**实测**：左 p50 **0.02129** / p95 0.02778 / max 0.02796 / mean 0.01588；
右 p50 **2.864e-5** / p95 0.004368 / max 0.005228 / mean 0.001169。
右脚裕度比左脚**小一个数量级**。min ≈ −3.7e−9 是浮点误差，按 ≥ 0 处理。

**判读**：≥ 0（凸组合保证）。接近 0 = 支撑裕度耗尽。

**坑（两条）**：

1. 是到**接触 taxel 凸包**（不是脚掌物理外缘）的距离——小裕度指载荷全挤在接触区某条边，
   **不等于**脚踩到物理边缘。
2. **32 向采样给出的是真值的上界（高估）**，不是低估：对 u 取子集再求 min，子集上的 min 恒
   ≥ 全集上的 min。高估约毫米量级（在边法向方向被采到时才取到真值）。

### `foot_friction_margin_n/{left,right}` — 摩擦裕度

**单位** N · **参考系** 无 · **源** 传感器 · **瞬时量**

```
mu = env.sim.model.geom_friction[:, foot_geom_ids, 0].mean(-1)
friction_margin = mu * force_n - force_t
```

**含义**：可用最大切向摩擦力 μF_n 减当前切向力 F_t。**≥ 0 未滑，< 0 已滑。是力的量纲，不是系数。**

**实测**：左 p50 30.37 / p95 56.95 / max 75.45 / mean 21.19；右 p50 27.87 / p95 49.76 /
max 63.84 / mean 21.80。左右均值接近。

**判读**：接触时越大越安全。本录接触帧 p50 ≈ 28–30 N。

**坑**：**悬空帧恰为 0**（两力都 0），看起来像濒临打滑其实没接触——`reduce="mean"` 会被
大量 0 稀释。用的是两脚全部足底 geom 的**同一个 μ 均值**。

---

### `foot_friction_util/{left,right}` — 摩擦利用率

**单位** 0~1（可 > 1）· **参考系** 无 · **源** 传感器 · **瞬时量**

```
friction_util = where(force_n > 1e-3, force_t / (mu * force_n).clamp(min=1e-6), 0)
# 等价于 1 - friction_margin / (mu * force_n)
```

**含义**：**0 = 无切向负载或无接触，1 = 到摩擦极限（将滑），> 1 = 已滑。**

**实测**：左 p50 0.1632 / p95 0.3286 / max **1.0000001** / mean 0.1537；
右 p50 0.1473 / p95 0.3889 / max 0.7072 / mean 0.1443。
**左脚有一次触到极限**（仅 1 帧 ≥ 1.0）。

**判读**：接触时看是否逼近 1。这是最该配**红色阈值线 y = 1.0** 的一列。

**坑**：悬空帧被 guard 成**精确 0**（不是 NaN）——0 不代表离打滑很远，而代表没接触。
`reduce="max"`（峰值利用率），不是 mean。

### `foot_ground_friction_mu` — 足底摩擦系数（单列）

**单位** 无量纲 · **参考系** 无 · **源** 模型参数 · **逐步读**

```
mu = env.sim.model.geom_friction[:, foot_geom_ids, 0].mean(-1)
```

**含义**：模型里足底碰撞 geom 与地面之间的滑动摩擦系数，左右两脚全部足底 geom 取均值。

**实测**：n=200，**恒为 0.851664**，std = 0（全程常数）。

**判读**：play/录制未开摩擦 DR 所以是常数；**开了 DR 才会逐 episode 变**。单列覆盖左右脚。

**坑**：是**模型参数不是实测摩擦**；是左右脚**合并**的单值（不是逐脚列）。
别把它当每帧变化的量画成时间序列——画成统计磁贴/图注更合适。

## F. 滑移与整机

**全部左右标签正确**（走 site / 传感器 / 关节路径）。

### `foot_contact_slip_speed_m_s/{left,right}` — 接触脚水平速度

**单位** m/s · **参考系** 世界系 · **源** site + 传感器 · **瞬时量**

```
foot_speed = norm(site_lin_vel_w[:, site_ids, :2], dim=-1)
slip_speed = foot_speed * contact
```

**实测**：左 p50 0.0260 / p95 0.1094 / max 0.1926；右 p50 0.0248 / p95 0.1443 / max **0.5714**。
右脚步态存在明显打滑尖峰，左脚没有。

**判读**：支撑脚应 ≈ 0；**> 0.2 m/s 视为拖脚**（与 `foot_slide_fraction` 同口径）。
逐帧抖动大，判"这一步滑没滑"用 `foot_slip_speed_peak_m_s`。

**坑**：乘了 `contact`，所以 **0 有两种含义**：脚静止，或脚腾空。

---

### `foot_contact_slip_dist_m/{left,right}` — 本次支撑累计滑移

**单位** m · **参考系** 世界系 · **源** site + 传感器 · **区间累计量**

```
rising = (contact > 0.5) & (prev_contact <= 0.5)
slip_dist = where(rising, 0, slip_dist) + step_dist * contact * (~rising)
```

**实测**：左 p50 0.00959 / p95 = max 0.01587；右 p50 0.01165 / p95 = max 0.01973。
右脚每步累计滑移略大（p50 约 +21%）。

**判读**：越小说明支撑脚越接近"钉住"；累计到厘米量级说明整个支撑相脚在持续移动
（含正常重心转移）。**无固定阈值**，看趋势/左右对比。

**坑**：触地那一帧的位移发生在腾空段，被 `(~rising)` 排除。**每步触地归零，跨步不累计**——
不要当成 episode 累计位移。

---

### `foot_slip_speed_peak_m_s/{left,right}` — 本次支撑滑移峰值

**单位** m/s · **参考系** 世界系 · **源** site + 传感器 · **锁存量**

```
slip_peak = where(rising, 0, slip_peak)
slip_peak = maximum(slip_peak, slip_speed)
```

**实测**：左 p50 0.1198 / p95 = max 0.1926；右 p50 0.3008 / p95 = max **0.5714**。
右脚峰值约为左脚的 **2.5–3 倍**（p50 比 2.51 / mean 比 2.69 / max 比 2.97）。

**判读**：**> 0.2 m/s 即该支撑相出现过打滑**。比瞬时列更适合判"这一步滑没滑"。

**坑**：锁存量（支撑内 max），腾空时保留上一次支撑的峰值不更新。
左列 max 恰等于 p95，说明左脚步态高度重复、无离群尖峰。

---

### `foot_slip_velocity_m_s` — 接触脚平均滑移速度（单列）

**单位** m/s · **参考系** 世界系 · **源** site + 传感器（`pikachu_metrics.py`）

```
sum(foot_speed * in_contact) / clamp(sum(in_contact), min=1.0)
```

**含义**：两脚中**当前接触脚**的水平速度均值（整机一个标量）。

**实测**：min 0 / p50 0.0470 / p95 0.1400 / max 0.3623 / mean 0.0590。

**判读**：0 = 接触脚全静止；越大说明支撑脚在拖/滑。与离线脚本 `stance_slip_mean` 同口径。

**坑**：分母 `clamp(min=1.0)`——**双脚都腾空时结果为 0**（0/1），不是 NaN。
与 `foot_contact_slip_speed_m_s` **不是同一列**（后者逐脚、乘 contact 掩码），别混用。

### `foot_slide_fraction` — 滑移脚占比（单列）

**单位** 0~1（**离散，只有 {0, 0.5, 1}**）· **参考系** 无（判据基于世界系水平速度）·
**源** site + 传感器（`pikachu_metrics.py`）

```
sliding = (foot_speed > 0.2).float() * in_contact
sum(sliding) / clamp(sum(in_contact), min=1.0)
```

**实测**：p50 = p95 = 0，max **0.5**，mean 0.0175。绝大多数帧为 0，仅少数帧达 0.5，
**全程没有到过 1.0**（两脚同时滑）。

**判读**：0 = 接触脚都钉住，0.5 = 一只在滑，1 = 两脚都滑。阈值 **0.2 m/s**。

**坑**：**只有三个取值，不是连续量**——画成折线会暗示不存在的中间值，应画成阶梯带/事件刻度。
阈值 0.2 硬编码在函数签名默认值里。

### `foot_lateral_separation_m` — 双脚横向间距（单列）

**单位** m · **参考系** **base 朝向系（仅去 yaw）** · **源** site（`pikachu_metrics.py`）

```
delta_b = quat_apply_inverse(yaw_quat(root_quat_w), pos_w[:, 0] - pos_w[:, 1])
out = abs(delta_b[:, 1])
```

**实测**：min 0.1069 / p50 0.1327 / p95 0.1580 / max 0.1716 / mean 0.1344，std 0.0150。
走前进档时开度稳定在 10.7–17.2 cm。

**判读**：反映走路时双脚张开的宽度；与站立门控 `feet_lateral_distance` 同算法。

**坑**：**只去 yaw，没去 base 的 pitch/roll**——机体倾斜会泄漏进来。取 |Δy| 丢了哪只脚在左。
必须去 yaw 的理由：世界系 y 差会随转身按 cos(yaw) 缩水。

### `base_roll_deg` — 机体横滚角（单列）

**单位** deg · **参考系** 世界系 · **源** `projected_gravity_b`

```
base_roll = rad2deg(atan2(-gravity_b[:, 1], -gravity_b[:, 2]))
```

**实测**：min −6.007 / p50 0.1695 / p95 5.963 / max 6.310 / mean **0.0098**，std 4.212。
均值几乎为 0，峰谷约 ±6°，左右对称摆动，**无系统性倾斜**。

**判读**：零附近 = 站直；持续偏向一侧说明重心/步态不对称。`reduce="max_abs"`。

**坑**：必须用 `atan2(-g_y, -g_z)` 而非 `asin(g_y)`——**后者整体反号**。
与 `foot_roll_deg` 同正负约定（正 = 绕世界 +x 右手正转 = 左侧(+y)抬起、向右倾）。

### `base_roll_rate_rad_s` — 机体横滚角速度（单列）

**单位** rad/s · **参考系** base body 系 x 轴 · **源** `root_link_ang_vel_b[:, 0]`

**实测**：min −2.155 / p50 −0.1798 / p95 1.842 / max 2.398 / mean −0.0126，std 1.050。
峰谷约 ±2.4 rad/s，均值近 0。

**判读**：零 = 无横滚转动；峰值大 = 触地/摆动时躯干猛晃。`reduce="max_abs"`。

**坑**：是 base body 系横滚轴**角速度**，**不是** `base_roll_deg` 的数值微分，也不是世界系量。
带符号（live 值有正负，episode 摘要才取 max_abs）。量纲与 `base_roll_deg` 不同，**不可共 y 轴**。

### `joint_torque_rate_nm_s/{joint_name}` — 关节扭矩变化率

**单位** N·m/s · **参考系** 无 · **源** `qfrc_actuator`（差分）· **瞬时量** · **每驱动关节一列**

```
torque = entity.data.qfrc_actuator[:, joint_ids]
joint_torque_rate = abs(torque - prev_joint_torque) / step_dt
```

**含义**：逐驱动关节的 |dτ/dt|——触地冲击负载。

**实测**（v031，10 关节）：

| 关节 | 左 p50 / max | 右 p50 / max |
|---|---|---|
| `hip_pitch` | 27.5 / **191.1** | — / 174.7 |
| `knee_up` | 42.2 / 174.1 | — / 173.4 |
| `hip_roll` | — / 135.5 | — / 155.4 |
| `ankle` | — / 136.4 | — / 143.0 |
| `hip_yaw` | — / **57.5** | — / 71.8 |

膝与髋 pitch 峰值最高（170–191），hip_yaw 最低（57–72）。

**判读**：**瞬时量不是峰值**——峰值要对列取 max。触地瞬间冲击会让它尖峰。
"哪个关节被冲击最大"用峰值柱状图直接回答，不要叠 14 条曲线。

**坑**：用 `qfrc_actuator`（执行器输出扭矩）差分，不是关节净力。**列名随关节表变化**——
v031 的驱动关节是 `knee_up` 而不是 `knee`。只有注册进 `joint_names` 的关节才有列。
