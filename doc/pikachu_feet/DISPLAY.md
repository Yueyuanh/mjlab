# 足底遥测展示形式规范

> 本文回答 [README.md](README.md) 里的第二个问题：**每一项应该用什么形式展示**。
> 逐列的单位/公式/实测见 [COLUMNS.md](COLUMNS.md)。
>
> 核心判断只有一句：**图的形式必须匹配数据的形状**（shape → form）。
> 时序连续量用折线、区间状态用色块、二维场用热力图、锁存量用每步事件点、
> 离散比例用阶梯带。**形状用错，读者看到的就不是数据。**

---

## 0. 三条跨组铁律

这三条不遵守，后面每组画得再对也会被误读。

### 2026-10-15 显示复核后的口径

以下规则是当前页面行为；本文中的旧日志数值仅为历史示例，不能当新 CSV 的结论。

| 数据类型 | 当前展示 |
|---|---|
| 触地状态、相位 | 左右区间条 + 相位时序，密集切换线不逐条打印时间 |
| 连续力、姿态、滑移速度 | 同单位时序；量纲不同拆图或明确双轴，注明触地区间 |
| 接触计数、面积占比 | 阶梯图，计数/占比/面积只画代表量，其余保留悬浮读数 |
| 压力空间代理 | 单帧回放或区间聚合场，+x 向上、+y 向左、80:56 等比例 |
| CoP 二维位置 | 各脚独立 XY 图，时间色标、缺失断线，窄屏上下排列 |
| 每步锁存/累计量 | 触地事件图 + 按单位分开的箱线图，显示步数 n |
| μ | 数值磁贴与范围统计；区间内恒定不能证明训练/reset 没有 DR |

所有图加独立标题；长说明移到画布外换行，不挤坐标轴。窄窗口不强制双列。
未知字段只保留原始统计，缺列或当前区间全缺失的图隐藏，有限的 0 仍是有效数据。
PDF 复用专用图与注释，压力导出区间聚合图；不再退回跨单位总览。

**每步口径**：真实触地需有前一帧离地证据，区间首帧在支撑中不能算新触地。
占空比在每次真实触地取上一周期的一个有效值，数值相同的不同周期仍分别计数；
落地角每次事件一个样本。冲击峰值/加载率、每步滑移峰值/累计量仅统计在选区内
有完整起止证据的支撑段，排除录制起止及范围裁剪的半步。触地占比以有限样本为分母。

**质量/几何口径**：不写死机器人质量；填写整机质量后才给 mg，未填只画实测
总法向力均值并明确“非 mg”。当前 V031 XML 名义 taxel 中心为 x=±40、y=±28 mm；
CoP 灰框是这一名义网格，不是每帧真实接触凸包，也不是脚掌外轮廓。
压力由同名脚力值按几何权重分摊，CoP/面积/穿透/裕度同属采样代理。
历史 CSV 可能含旧的左右索引问题，页面保留 CSV 侧别，不猜测交换、不改原始值。

复核使用 `doc/code_sync_20261015/metrics/metrics_v03_fwd_mirror005-server-smoke.csv`，
对照 `src/mjlab/tasks/pikachu_foot_telemetry.py`；浏览器检查覆盖 6 页 × 4 种宽度
（1440/1100/768/390），另用合成步态检查重复占空比、截断区间、缺失值与左右提示。

### 铁律一：共享同一根时间轴，并把触地区间当底衬

所有"随时间"的量必须共用同一条 `DATA.time` 与同一个缩放/range 控件。

更重要的是：**A 组的触地区间要作为其余所有时序图的背景遮罩。**
因为大量列的 0 是"腾空造成的假 0"，不叠接触条必然误读：

| 列 | 值为 0 时的两种含义 |
|---|---|
| `foot_contact_slip_speed_m_s` | 脚没滑 **或** 脚腾空 |
| `foot_friction_util` | 离打滑很远 **或** 没接触（被 guard 成 0） |
| `foot_friction_margin_n` | 摩擦裕度耗尽 **或** 没接触 |
| `foot_contact_area_m2` / `foot_penetration_m` | 真无接触 **或** 只是没有 taxel 低于地面平面 |

同时，B / D / F 三组的**触地（rising）事件必须在同一 x 位置标出**，
才能对齐"落地瞬间"的力峰、姿态角与滑移尖峰。

### 铁律二：不同量纲绝不共 y 轴

| 不能同轴 | 原因 |
|---|---|
| `foot_force_normal_n` (N) 与 `foot_force_rate_n_s` (N/s) | 量级差约 50 倍，小量被压平 |
| `base_roll_deg` (deg) 与 `base_roll_rate_rad_s` (rad/s) | 量纲不同，数值无共同尺度 |
| `foot_cop_x_m` (m) 与 `foot_contact_slip_speed_m_s` (m/s) | 位移 vs 速度 |

要叠就双 y 轴并**明确标注哪条读哪轴**，否则分图。

### 铁律三：锁存量/区间量进"每步事件"图，不与瞬时量混在折线语义里

以下列是**每次触地归零的区间量**，整段支撑内保持不变：

`foot_impact_peak_n`、`foot_impact_rise_n_s`、`foot_touchdown_{pitch,roll,tilt}_deg`、
`foot_contact_slip_dist_m`、`foot_slip_speed_peak_m_s`、`foot_duty`（上一周期锁存）。

逐帧折线会画出**误导性的阶梯**（中间帧无新信息）。
正确形式：x = 触地序号或触地时刻，y = 该次支撑的值（点图或柱状），
或作为**包络阶梯**叠在对应的瞬时量曲线上。

## 1. A 组 · 步态相位与计时

**形状**：区间状态 + 锯齿 + 锁存阶梯的混合。
`foot_contact` 是逐帧 0/1 阶跃；`foot_phase` 是每次触地重置、环绕到 1 的锯齿；
`foot_stance_time_s` / `foot_air_time_s` 是"进行中计时器"锯齿（接触中 +dt、离地清零）；
`foot_duty` 是每次支撑↔腾空跃迁才更新的锁存阶梯。

**推荐形式 —— 甘特式区间条 + 共享 x 轴的相位带**

```
时间 →
┌─────────────────────────────────────────┐
│ 左脚  ████████░░░░░░░░████████░░░░░░░░  │  ← 触地区间矩形块（蓝）
│ 右脚  ░░░░████████░░░░░░░░████████░░░░  │  ← 触地区间矩形块（红）
├─────────────────────────────────────────┤
│ phase ╱|╲  ╱|╲  ╱|╲  ╱|╲  （0→1 锯齿）  │  ← 每次触地重置
│   0.5 - - - - - - - - - - - - - - - - -  │  ← 反相参考线
└─────────────────────────────────────────┘
```

- x = 时间，y = 左/右两行，每个连续触地区间画一条矩形块。
- 下方紧贴一条**共享 x 轴**的 `foot_phase` 锯齿带（0→1 环绕，每次触地重置，前 2 帧 NaN 断开）。
- 每次换脚画竖直标记线。
- 区间统计（占空比 %、平均支撑/腾空/周期、触地次数）作为**图注文本**，不占图位。

**为什么**：步态的本体是"这只脚什么时候在地上"。区间块把 0/1 状态直接画成**有长度的色块**，
单/双支撑交替与节律一眼可读。`foot_phase` 只在一次触地→下次触地之间有意义，
做成与区间条同轴的锯齿带能看出相位是否匀速推进、左右是否约 180° 反相。

**反例**：

- ❌ 用折线画 `foot_contact`——把 0/1 阶跃连成斜线，暗示不存在的连续过渡。
- ❌ 把 `foot_stance_time_s` / `foot_air_time_s` 对整段取均值画单值。
  它们是**进行中计时器**（腾空时 stance 恒 0、支撑时 air 恒 0），
  均值被 0 稀释成半个周期（本录 stance mean 0.078 s 而真实单次支撑 0.28 s）。
  **时长必须由触地区间反推，不能读这两列。**
- ❌ 把 `foot_duty` 折线化当瞬时量读——它是上一次完整周期的锁存值。

**元素清单**：左右两行共享时间轴 · 触地区间矩形块（左蓝右红）· 换脚竖直标记线 ·
phase 带上的 0.5 参考线 · 占空比%/支撑/腾空/周期/触地次数图注 · NaN 断点。

## 2. B 组 · 接触力与冲击

**形状**：混合。`foot_force_normal_n` / `foot_force_tangent_n` 是连续时序
（每步一峰的准方波脉冲，腾空为 0）；`foot_force_rate_n_s` 是带符号冲击脉冲
（±2000~4900 N/s 尖峰，稳态为 0）；`foot_impact_peak_n` / `foot_impact_rise_n_s`
是每次触地归零的锁存包络。

**推荐形式 —— 堆叠面积 + 独立的脉冲图 + 每步事件柱**

```
图 1：法向力堆叠面积                    图 2：力变化率竖干图
  N ▲                                    N/s ▲
100─┤      ▓▓        ▓▓                   5k─┤  │    │
 66─┼━━━━━━━━━━━━━━━━━━━━ ← mg 参考线     0─┼──┴────┴──────
  0─┤▓▓░░▓▓░░▓▓░░▓▓░░▓▓                      │  │    │
    └──────────────────→ 时间             -3k─┘  ▼    ▼
```

- 主图：左右脚法向力**堆叠面积**（堆叠顶 = 地面总支持力），有明确整机质量才叠 **mg 水平参考线**；否则仅标实测总力均值。
- 切向力同轴**虚线**（不堆叠）——它与法向不同向，叠加无物理意义。
- `foot_force_rate_n_s` **另起一张共享 x 轴的竖干/脉冲图**（0 基线、正负尖峰）。
- `foot_impact_peak_n` / `foot_impact_rise_n_s` 用**每步事件图**：
  x = 触地序号或触地时刻，y = 该次支撑内的峰值（点或柱），左右分色。

**为什么**：堆叠让"**总支持力恒 ≈ mg**"这一物理约束一眼可验——本录实测左右均值之和
68.17 N vs mg 66.42 N（历史示例）。动态运动时总力可随竖直加速度正常偏离 mg，
不能仅由瞬时偏离认定接触丢失或模型错误。
rate 是 50 Hz 差分的冲击，量级与力差约 50 倍，**必须独立轴/图**；
impact_* 天然是"每步一个值"的锁存量，逐帧折线会画出误导性阶梯。

**反例**：

- ❌ 把 `foot_force_rate_n_s` 与法向力放同一 y 轴（量级差约 50 倍）。
- ❌ 把 `foot_impact_peak_n` 当瞬时法向力读（锁存量，整段支撑内不变）。
- ❌ 用整段均值汇总 rate——正负抵消成 ~0（本录左 mean 15.59、右 mean ≈0），
  卸载负峰（左 min −2902.79 N/s）被完全抹掉。
- ❌ 把左右切向力堆叠。

**元素清单**：堆叠面积（左右分色）· mg 参考线（虚线 + 数值标注）· 0 基线 ·
rate 竖干图的正负尖峰 · 每步峰值柱按左右分色 · 可选触地冲击阈值线。

## 3. C 组 · 接触几何与压力

**形状**：混合。`foot_penetration_m` 是逐帧连续标量；
`foot_contact_area_m2` / `foot_contact_fraction` / `foot_sensor_count` 是**同一接触计数的三种换算**
（计数 0~25 整数、占比 0~1 步长 1/25、面积 k·cell_area）；
`foot_pressure_pa` 是**二维场**（每脚 25 taxel × 时间，共 50 列）。

**推荐形式 —— 一列代表 + 参考线 + 两张压力热力图**

- **面积组三列只画一列**（推荐 `foot_contact_fraction` 作 0~100% 填充面积图，
  或 `foot_sensor_count` 作整数阶梯），另两列进 tooltip / 汇总表。
- `foot_penetration_m` 用折线 + **2 mm（`SOLE_COMPLIANCE_M`）参考线**。
- `foot_pressure_pa` 用**两张互补图**：

```
(a) 时间 × taxel 热力图                (b) 5×5 足形空间热力图
     时间 →                                    列 x →
 L00 ░▒▓█▒░                            ┌───┬───┬───┬───┬───┐
 L01 ▒▓█▓▒░                            │   │ ▒ │ ▓ │ ▒ │   │
 ...                                   ├───┼───┼───┼───┼───┤
 R44 ░░▒▒░░                            │ ▒ │ ▓ │ █ │ ▓ │ ▒ │  ← 每脚一张
                                       └───┴───┴───┴───┴───┘
```

**为什么**：面积/占比/计数是**同一计数的三次换算**，叠三列会完全重合、浪费图位。
penetration 的 2 mm 是本模块唯一建模假设，越过它几何代理与真实接触分家，必须画成参考线。
压力是二维场，折线/堆叠都表达不了空间分布，**热力图是唯一合适形式**，
且足形网格比一维 taxel 序列更贴近"脚掌哪里受压"。

**反例**：

- ❌ 叠 50 条 taxel 折线（无可读性）。
- ❌ 把 area / fraction / count 当三个独立指标各画一图。
- ❌ 用连续色标暗示 `sensor_count` 平滑（它是 26 级离散）。
- ❌ 把 clamp 后的 `penetration = 0` 读成"无接触"。

新录制的 taxel 几何列已按踝 body 名称与物理 left/right 对齐；修复前的历史 CSV 仍可能左右相反。

**元素清单**：2 mm 参考线（`SOLE_COMPLIANCE_M`）· 26 级阶梯/面积填充 ·
5×5 足形网格（L/R 分图，`k = y*5 + x`）· 蓝→绿→黄→红色阶 · 色标 p99 截断（防 `right_foot4`
的 285 kPa 尖峰压平全图）· taxel 标签 `L00..R44` 与 (x, y) mm tooltip。

## 4. D 组 · 足底姿态

**形状**：混合。`foot_tilt_deg` / `foot_pitch_deg` / `foot_roll_deg` 是逐帧连续时序
（支撑相小、摆动相大；pitch/roll 带符号、tilt ≥ 0）；
`foot_touchdown_{pitch,roll,tilt}_deg` 是每次触地锁存、整段支撑与随后腾空不变的阶梯。

**推荐形式 —— 三线共享时间轴 + 每步落地点**

- `tilt` / `pitch` / `roll` 三线共享时间轴，左右脚分色。
- `pitch` / `roll` 带符号，**必须画 0° 参考线**；`tilt` 作 ≥0 的阴影包络。
- `foot_touchdown_*` 用**每步事件点图**（x = 触地时刻，y = 该次落地角），
  并把这些点**叠在对应的连续 pitch/roll 折线上**，标出"落地点"在摆动曲线上的位置。

**为什么**：姿态角在支撑相与摆动相语义不同，连续折线能看出摆动摆幅与支撑是否踩平；
pitch/roll 有符号须绕 0 读，tilt 是二者合成包络（`sin²tilt = sin²pitch + sin²roll`，
可作交叉校验）。touchdown_* 是锁存量，画成每步一个点才如实反映"落地那一刻的姿态"。

**反例**：

- ❌ 把 `touchdown_*` 画成连续折线并在两次触地之间读数（中间帧无意义）。
- ❌ 把 `tilt`（≥0）与 `roll`（±）不区分符号地放同一"角度"轴。
- ❌ 用整段均值汇总 `touchdown_*`（每次落地角不同，均值抹掉分布；
  且首次触地前初值 0 会污染统计）。

新录制的姿态与 touchdown 列已按同名物理脚配对；修复前的历史 CSV 仍可能反向或交叉配对。

**元素清单**：0° 参考线（pitch/roll）· ±5° 或 ±10°"踩平"阈值带 · tilt 阴影包络 ·
触地点标记（落在连续线上）· 每步落地角点图按左右分色 ·
三列 touchdown 的 `sin²tilt = sin²pitch + sin²roll` 交叉校验。

## 5. E 组 · CoP 与摩擦

**形状**：混合。`foot_cop_x_m` / `foot_cop_y_m` 是踝体系**二维点轨迹**（腾空 NaN）；
`foot_cop_margin_m` 是 ≥0 连续标量（腾空 NaN，0 = 贴支撑边界）；
`foot_friction_util` 是 0~1 比率（1.0 = 打滑）；
`foot_friction_margin_n` 是带符号力（腾空恰为 0）；
`foot_ground_friction_mu` 是逐 env 标量参数（录制中恒定 0.8517）。

**推荐形式 —— 足平面轨迹图 + 裕度折线 + 阈值线 + 磁贴**

```
CoP 足平面轨迹（左脚一张，右脚一张）      裕度 / 摩擦
   y ↑                                     util ▲
+28mm┤  ·····                            1.0 ┼━━━━━━━━━━ ← 摩擦边界阈值
     │ ······  ······                       │    ╱╲
-28mm┤      ······                        0.0 ┼───┴──┴─────
     └───────────────→ x
    -40mm        +40mm
   ┄┄ 名义采样网格框（非当前接触凸包）
```

- CoP 用**足平面 xy 散点/轨迹图**（x = 脚掌 x mm，y = 脚掌 y mm），
  叠加 25 taxel 中心的**名义网格框**（非实际接触凸包），轨迹点按时间着色，左右脚**分图**。
- `foot_cop_margin_m` 单独一条共享 x 轴时间折线 + 0 参考线。
- `foot_friction_util` 时间折线 + **y = 1.0 红色阈值线**；`foot_friction_margin_n` 走右轴（量纲不同）。
- `foot_ground_friction_mu` 做成**统计磁贴/图注**，不画时间序列。

**为什么**：CoP 的唯一意义是"在脚掌平面哪个位置、离支撑边界多远"，
拆成 cop_x / cop_y 两条对时间的一维曲线**恰好丢掉这个空间信息**。
margin 是到接触采样凸包的距离代理，0 不是整机翻倒判据；util 到 1 表示到达摩擦边界，
是否正在滑动仍需结合滑移速度。
mu 在录制中恒定，画成线是浪费。

**反例**：

- ❌ 把 `cop_x` / `cop_y` 各画一条时间折线（丢失"脚掌上哪个位置"）。
- ❌ 把腾空 NaN 连起来（`connectNulls` 必须 false，否则把两次触地间连成假轨迹）。
- ❌ 把 `friction_margin = 0` 读成"安全"（腾空时恰为 0）。
- ❌ 把 `friction_util = 0` 读成"离打滑很远"（腾空被 guard 成 0）。
- ❌ 给 `foot_ground_friction_mu` 画时间序列。
- ❌ 把左右脚 CoP 放同一坐标系比绝对值（各自踝体系原点/朝向不同）。

CoP 与摩擦列在新录制中都按实际物理脚标记；CoP 仍处在各自踝体系，跨脚不比较绝对坐标。

**元素清单**：支撑多边形虚线边界（taxel 中心约 ±40 × ±28 mm）· CoP 散点按时间/裕度着色 ·
margin = 0 参考线 · util = 1.0 红色打滑阈值线 · 左右分图（跨脚不可比绝对值）·
mu 统计磁贴 · NaN 断点。

## 6. F 组 · 滑移与整机

**形状**：混合。`foot_contact_slip_speed_m_s` 是逐脚连续时序（乘了 contact，腾空为 0）；
`foot_contact_slip_dist_m` 是支撑内单调累计、每次触地归零的锯齿；
`foot_slip_speed_peak_m_s` 是区间锁存；`foot_slip_velocity_m_s` 是整机连续标量；
`foot_slide_fraction` 是**离散阈值判据 {0, 0.5, 1}**；
`foot_lateral_separation_m` / `base_roll_deg` / `base_roll_rate_rad_s` 是整机连续标量；
`joint_torque_rate_nm_s` 是逐关节的冲击脉冲。

**推荐形式 —— 门控折线 + 每步柱 + 离散阶梯带 + 关节峰值柱**

- **滑移**：逐脚 slip_speed 折线 + **0.2 m/s 打滑阈值线**，
  并用**接触阴影**标出"仅在接触帧判读"；`slip_speed_peak` 作每步点/柱；
  `slip_dist` 作"每步累计滑移柱"（而非锯齿折线）；
  整机 `slip_velocity` 折线、`slide_fraction` 作**离散阶梯带或红色事件刻度**。
- **整机姿态**：`lateral_separation` / `base_roll` / `base_roll_rate` **各自独立小图**
  （0 参考线），不共 y 轴。
- **关节冲击**：`joint_torque_rate_nm_s` 用**每关节峰值柱状图**（按关节排序、左右分色）
  或 时间×关节 热力图，**不叠 14 条线**。

**为什么**：滑移只有接触帧才有意义，接触阴影/门控是判读前提；
0.2 m/s 是与 `foot_slide_fraction` 同口径的判据线；dist/peak 是区间量，每步一柱/一点才如实；
`slide_fraction` 只有 {0, 0.5, 1} 三个值，阶梯带/事件刻度比折线诚实；
roll (deg) 与 roll_rate (rad/s) 量纲不同必须分轴；
14 条关节冲击曲线叠线不可读，**峰值柱或热力图直接回答"哪个关节被冲击最大"**
（本录：膝/髋 pitch 峰值 170~191 N·m/s，hip_yaw 最低 57~72）。

**反例**：

- ❌ 读 `slip_speed = 0` 为"没滑"（0 可能是腾空）。
- ❌ 把 `slide_fraction` 画成连续折线（离散量，只有 3 个取值）。
- ❌ 把 `base_roll_deg` 与 `base_roll_rate_rad_s` 同轴。
- ❌ 把 14 条 `joint_torque_rate` 叠一张折线图。
- ❌ 把 `slip_dist` 的归零锯齿直接取均值。

**元素清单**：0.2 m/s 滑移阈值线 · 接触帧阴影/门控 · 离散值阶梯带 ·
roll/rate 的 0 参考线 · 关节峰值柱按左右分色并排序 · 时间×关节热力图（可选）·
"`joint_torque_rate` 仅对峰值判读"的提示。

**容器高度（历史 bug，已修）**：ECharts 按容器的 `clientHeight` 建画布，而每个渲染
函数开头都会 `el.innerHTML=''` 清掉占位符——占位符一没，div 就塌成 0 高，画出来是一张
空图。此前 CSS 里没有任何 `#foot-*-chart` 高度规则，所以足底所有专用图实际都不可见。
现在统一由 `#foot-panel > div[id$="-chart"]` 给 260 px 基准高，再按图形需要逐个覆盖
（热力图时间轴 640 px、CoP 平面 400 px、三格姿态图 430 px…），容器同时加
`position:relative` 以承载足形图的「峰值/均值」切换按钮。

**历史 CSV 边界**：修复前数据仍保留旧左右索引；需要分析时按 [README 3.1](README.md#31-左右脚索引)
理解历史口径。修复后重新录制的 CSV 无需左右对调。
