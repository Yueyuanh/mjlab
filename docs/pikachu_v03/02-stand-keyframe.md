# 02 · 站立 keyframe 标定：从「脚在髋下」到「质心在脚心上方」

**脚本**：`scripts/probe_v03_both_legs.py` → `scripts/refine_v03_keyframe.py`
**产物**：`pikachu_v03_constants.py` 里的 `KNEES_BENT_KEYFRAME`

这是本次接入中**最容易被跳过、但跳过就白训**的一步。

---

## 为什么需要标定

v03 的 `qpos = 0` **不是站立姿态**：此时踝在 base 原点后方 10.7 cm
（腿后倾 27°），脚掌虽然水平，但撑在身后，机器人会向后倒。

必须解出一组关节角，让脚掌正确地撑在身体下方。

---

## 第一步 · 双腿独立解（`probe_v03_both_legs.py`）

**目标**：脚掌俯仰 = 0°，脚心 x = 0（即脚掌摆在 base 原点正下方）。

用源模型（`base_link` 焊死、**关重力**）解 —— 焊死时 `subtree_com` 直接给出
base 系下的质心，且关重力后 `<connect>` 约束精确收敛、PD 无稳态误差。

有限差分雅可比 + 牛顿迭代（`e=1e-3`，步长裁剪 ±0.2，10 次迭代）：

```

     0.00  -0.4822  -0.5074 |      -0.00  -0.4802   0.5048 |  0.27286
    -0.20  -0.5430  -0.3892 |       0.20  -0.5410   0.3873 |  0.26963
```

### 副产物：实测的左右轴镜像规则

这是 v03 **最容易踩的坑** —— **左腿不是整体镜像**。实测 `jnt_axis`：

| 关节 | 右轴 | 左轴 | 左右 |
|---|---|---|---|
| `hip_pitch` | `[0, 1, 0]` | `[0, 1, 0]` | **同向** |
| `hip_roll` | `[1, 0, 0]` | `[1, 0, 0]` | **同向** |
| `hip_yaw` | `[-.571, 0, .821]` | `[-.571, 0, .821]` | **同向** |
| `knee` | `[0, -1, 0]` | `[0, -1, 0]` | **同向** |
| `ankle` | `[0, -1, 0]` | `[0, 1, 0]` | **反号** |
| `knee_up` | `[0, -1, 0]` | `[0, 1, 0]` | **反号** |
| `knee_mid` | `[0, -1, 0]` | `[0, 1, 0]` | **反号** |

即髋三轴与膝轴左右**同号**，只有踝 / `knee_up` / `knee_mid` 因为 CAD 里对应
link 被镜像过而反号。实测比值证实：

```
knee_L/knee_R        = +1.0000    （同号）
knee_mid_L/knee_mid_R = -1.0000   （反号）
ankle_L/ankle_R      = -1.0000    （反号）
```

关节限位同样只对这三个镜像：右 `knee_up` `[-1.22, 0.52]` ↔ 左 `[-0.52, 1.22]`。

> **教训**：不要凭「人形机器人左右镜像」的直觉写 keyframe。写之前先打印
> `m.jnt_axis` 和 `m.jnt_range` 核对。我第一次就按整体镜像写了
> `left_ankle = -0.5148`，实际应该是 `+0.5048`。

## 第二步 · 固定点迭代到静平衡（`refine_v03_keyframe.py`）

### 为什么「脚心 x = 0」还不够

「脚心 x = 0」只是把脚摆在 **base 原点**正下方，而 v03 的质心在
**x = -0.0195 m**（base 原点后方 2 cm）。

于是重力矩持续把机器人往后压。零动作开环测试里它先向后仰 9.6°、base 掉到
0.2248 m，再被踝关节 PD 的弹性力矩拉回来，最后停在 **pitch = -0.167 rad
的非零平衡点**上。

那不是静平衡：真正的静平衡要求**质心水平投影落在支撑中心**，此时踝关节
PD 误差为 0，零动作就是不动点，episode 开局没有塌陷瞬态。

### 解法

```
cx_target ← 0
重复 8 次：
    解 hip/ankle 使 脚掌俯仰 = 0 且 脚心 x = cx_target
    量此时整机质心的 x → cx_target
```

收敛过程：

```
 iter   cx_target      CoM_x      脚心x_R      脚心x_L    base_z
    0     0.00000   -0.01744   -0.00000   -0.00000   0.26904
    4    -0.02651   -0.02678   -0.02651   -0.02651   0.26788
    7    -0.02690   -0.02691   -0.02690   -0.02690   0.26784   ← 收敛
```

### 收敛结果

```python
KNEES_BENT_KEYFRAME = EntityCfg.InitialStateCfg(
  pos=(0, 0, 0.26728),
  joint_pos={
    "right_hip_pitch_joint":  -0.4272,
    "left_hip_pitch_joint":   -0.4252,
    "right_knee_up_joint":    -0.2000,
    "left_knee_up_joint":     +0.2000,   # 左腿 knee_up 反号
    "right_ankle_joint":      -0.2747,
    "left_ankle_joint":       +0.2727,   # 左腿 ankle 反号
    "right_knee_joint":       -0.1775,
    "left_knee_joint":        -0.1775,   # 左腿 knee 同号
    "right_knee_mid_joint":   +0.2056,
    "left_knee_mid_joint":    -0.2056,   # 左腿 knee_mid 反号
    "hip_roll/hip_yaw":        0.0,
  },
  joint_vel={".*": 0.0},
)
```

### 两个附注

1. **被动关节 `knee` / `knee_mid` 必须写进 keyframe**。它们由
   `<connect>` 约束跟随 `knee_up`；如果留 0，reset 瞬间约束会把它们猛拽一下，
   注入能量。实测传动关系（关重力标定）：`knee_mid = -knee_up`（精确成立），
   `knee/knee_up` 在 0.45~1.16 之间随角度变化，零位有 +1.66° 偏置。

2. **微屈膝（`knee_up = -0.20`，膝屈 ~10.3°）不是随手选的**：四杆膝在
   `knee_up ≈ 0` 附近传动比最低（0.45~1.17 的下沿），微屈膝避开那个区段，
   也符合「走路时膝盖不锁死」的常识。

3. **高度 0.26728 是在训练模型（带 freejoint）里复核的权威值**。源模型
   （base 焊死）给出 0.26784，差 0.56 mm 来自基座朝向的自由度。
   复核同时得到：总质量 2.3814 kg、质心 x = -0.02683、约束残差 1.624e-04。

## 验收：零动作开环站立

```
  step    base_z      |v|     roll    pitch  knee_up_R    knee_R      足底力N
     0   0.26728  0.00000  -0.0000   0.0000   -0.20000  -0.17750   -19.883
    50   0.26734  0.00040  -0.0001  -0.0935   -0.24383  -0.23285   -23.362
   300   0.26731  0.00000  -0.0001  -0.0955   -0.24553  -0.23464   -23.362

最低 base_z : 0.26728 m
首次跌破 50% 高度: 未发生
终止 time_out / fell_over : 0 / 2408
✓ 开环站得住 → 模型没问题，可以开训
```

base 高度漂移 0.03 mm，速度归零，无 NaN，无终止。

**残留的 pitch = -0.0955 rad 是 PD 柔度平衡，不是 bug**：位置执行器刚度有限，
重力（23.4 N）把腿压到 PD 误差刚好提供保持力矩的地方（`knee_up` 从 -0.200
被压到 -0.2455）。这是闭环系统的真实平衡点，不需要也不应该「预先补偿」——
把 keyframe 设成这个姿态反而会让 PD 误差归零、继续下沉。

---

## 这一步没做会怎样

`pose` 奖励拿 `asset.data.joint_pos` 与 `default_joint_pos`（= keyframe）
比较。keyframe 不是平衡点时，**零动作的 `pose` 奖励就已经很低**，策略开局
面对的是一个自己往下掉的机器人 —— 学习信号被塌陷瞬态淹没，训练要么很慢
要么学出一个「一直用腿撑着」的怪姿态。
